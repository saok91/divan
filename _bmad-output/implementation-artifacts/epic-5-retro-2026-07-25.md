## What went well

- **Prep notes from 4b/4 paid off:** IDOR scope, PopulationPort honesty, leave-guard data-state rules, and profile/timeline consumer contract landed in 5.1–5.3 Gates before code — fewer “rediscover in review” loops on those themes.
- **Consume-not-reinvent held:** Lists bound to `GovernedDataTable` without primitive rewrite; profile/timeline consumed `getCurrentPersonState` + event-store APIs; dashboard/reports owned math in `@divan/reporting` with thin governed tRPC.
- **Fail-closed PopulationPort discipline:** 5.1 Decision rejected provisional stamp-all UUID map; empty population + Operator disclosure carried through 5.4/5.5 instead of fake production authz.
- **Reporting module birth with honest semantics:** Catalogue + assemble paths, suppress≠empty≠zero Persian oracles, as-of HC via historical ledger (not live free/wall-clock mix), soft-omit cards/keys without permission theater.
- **Export / Import Batch honesty:** 5.5 (and 5.1 export affordance) did **not** claim FR41/FR52 done; Import Batch outcomes return unavailable until Epic 6 — sprint planning cannot treat export as shipped.
- **Uniform IDOR posture on reads:** search/list/get/profile/timeline share scoped population asserts with uniform `PERSON_NOT_FOUND` anti-enumeration.
- **Dual-package selfcheck habit:** reporting + web selfchecks for dashboard and report; personnel helper selfchecks continued story-to-story.

## Challenges

- **Reporting state-machine / temporal patch load:** 5.4 and 5.5 absorbed heavy review patches (Effective vs Finalized counts, apply-path event load, as-of open HC, team filter semantics, truncation, filter validation, fail-closed copy). New aggregation surfaces still predict high review budget.
- **N+1 / MVP envelope debt:** Parallel `getCurrentPersonState` (≤500) on lists; per-subject employment/event loads on dashboard/reports — documented NFR-2 provisional, deferred repeatedly, still unpaid.
- **Selfcheck ceiling unchanged:** Helper-only oracles; DOM/keyboard/leave-guard/UJ paths remain manual DoD — Vitest/ephemeral isolation still open across Epics 3–5.
- **AC #1 search remainder deferred:** Dept/BU / national ID / email list-search identifiers not shipped; EXPERIENCE + phone + Job Title MVP only.
- **Lifecycle mutation IDOR gap:** 5.3 hardened `listForPerson` reads; Cancel/Reverse/Correct by `eventId` remain permission-only (pre-existing Epic 4 surface) — deferred, still real for Epic 6+ ops risk.
- **UTF-8 BOM on sprint-status:** Recurred (5.2/5.5 patches stripped BOM again). DoD exists; tooling still does not enforce.
- **4b technical carry still open:** Person-create form dedupe; logout/`router.replace` leave-guard bypass — not closed inside Epic 5.

## Key insights

1. **Consumer epics succeed when Gates encode prior retro debt** — 4b/4 action items #2–#4 completed into 5.1–5.3 Dev Notes and visibly shaped Decisions (fail-closed population, no parallel SoT, data-state leave-guard).
2. **Honesty beats provisional “green” authz** — empty PopulationPort + disclosure is better than stamp-all maps that would lie about production workforce scope.
3. **suppress≠empty≠zero is a product invariant for reporting** — once encoded in dashboard, reports reused it; Epic 6 reconciliation UIs must not regress to `0` for suppressed cohorts.
4. **Stub with a named successor story** — export and Import Batch stubs with explicit 6.5 / Epic 6 ownership prevented false “done” on FR41/FR52/FR38.
5. **Read-path IDOR ≠ write-path IDOR** — timeline list scope does not automatically close mutation-by-id gaps; carry mutation scope as named debt.
6. **Patch volume tracks new domain assemblers** — 5.1–5.3 (consume chrome + known APIs) lighter than 5.4–5.5 (new reporting assemble + temporal semantics).
